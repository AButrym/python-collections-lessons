Python Collections · Lesson 1

Counting things with Counter

Mission link: before any model sees your data, you will count labels, tokens and categories. Today's win: count and rank anything in one line, and avoid the traps that bite people in interviews and code review.

1. The problem you already know

With a plain dict you count like this:

counts = {}
for label in labels:
    if label in counts:
        counts[label] += 1
    else:
        counts[label] = 1

It works, but it is five lines of bookkeeping for one idea. The docs describe Counter as a "dict subclass for counting hashable objects" (docs).

2. The knowledge

from collections import Counter

labels = ['cat', 'dog', 'cat', 'bird', 'cat', 'dog']
c = Counter(labels)
c                # Counter({'cat': 3, 'dog': 2, 'bird': 1})
c['bird']        # 1
c['bacon']       # 0   (missing keys give 0, not KeyError)
c.most_common(2) # [('cat', 3), ('dog', 2)]

Keep three facts: it is a dict; a missing key counts as zero; most_common(n) returns the top n as (item, count) pairs, most frequent first. With no argument it returns all of them.

Other ways to build one

Counter('abracadabra')      # from any iterable
Counter(cat=3, dog=2)       # from keyword arguments
Counter({'cat': 3})         # from a mapping

Counters can be added and subtracted

Counter(a=3, b=1) + Counter(a=1, b=2)   # Counter({'a': 4, 'b': 3})
Counter(a=3, b=1) - Counter(a=1, b=2)   # Counter({'a': 2})

Useful for merging counts from two data shards. Note what happened to b in the subtraction: see pitfall 5 below.

4. Misconceptions and pitfalls

Each card is a belief that feels reasonable and is wrong. I ran every example below to confirm it.

You might think

Counter("the cat") counts the words.

Actually: a string is an iterable of characters, so Counter counts characters. Split first.

Counter("the cat")           # Counter({'t': 2, 'h': 1, 'e': 1, ' ': 1, 'c': 1, 'a': 1})
Counter("the cat".split())   # Counter({'the': 1, 'cat': 1})

You might think

Reading c['z'] adds 'z' to the Counter (like you will see with defaultdict next lesson).

Actually: reading a missing key returns 0 and does not insert it.

c = Counter('abracadabra')
c['z']        # 0
'z' in c      # False
len(c)        # 5

You might think

c.update(...) replaces counts, like dict.update.

Actually: on a Counter, update adds to the existing counts.

c = Counter(a=3); c.update(a=2, b=1)
c                      # Counter({'a': 5, 'b': 1})
d = {'a': 3}; d.update({'a': 2})
d                      # {'a': 2}   (dict replaces)

You might think

A count that drops to zero removes the key, and counts can never be negative.

Actually: the key stays, and negatives are allowed. The docs say counts "are allowed to be any integer value including zero or negative counts."

c = Counter(a=1)
c['a'] -= 1
c                  # Counter({'a': 0})
'a' in c           # True
c['b'] -= 2
c                  # Counter({'a': 0, 'b': -2})
list(c.elements()) # []      (elements() skips non-positive counts)
+c                 # Counter()   (unary + drops zero and negative)

You might think

Subtracting two Counters keeps negative results, like plain arithmetic.

Actually: the - operator keeps only positive counts. To keep negatives use c.subtract(other).

Counter(a=3, b=1) - Counter(a=1, b=2)   # Counter({'a': 2})   (b vanished)

You might think

most_common() returns a dict or Counter, so you can index it by label.

Actually: it returns a list of tuples. Use dict(c.most_common(3)) if you need a dict. For ties, my run on Python 3.14 listed items in first-seen order: Counter('bba').most_common() gave [('b', 2), ('a', 1)]. Do not rely on tie order without checking the docs.
