Python Collections · Lesson 2

Grouping with defaultdict

Mission link: grouping rows by a key (images by label, orders by customer) is daily bread in data work. Today's win: group without a single if key in d, and know exactly where defaultdict surprises people.

Builds on Lesson 1: Counter. Recall first: does reading Counter()['z'] add 'z'? (No.) Keep that in mind: defaultdict behaves differently.

1. The problem you already know

groups = {}
for label, path in rows:
    if label not in groups:
        groups[label] = []
    groups[label].append(path)

The if exists only to avoid a KeyError. defaultdict removes it.

2. The knowledge

The docs call defaultdict a "dict subclass that calls a factory function to supply missing values" (docs). You pass the factory when you create it:

from collections import defaultdict

rows = [('cat', 'a.jpg'), ('dog', 'b.jpg'), ('cat', 'c.jpg')]

groups = defaultdict(list)       # default_factory = list
for label, path in rows:
    groups[label].append(path)   # no "if label in groups" needed

groups   # defaultdict(list, {'cat': ['a.jpg', 'c.jpg'], 'dog': ['b.jpg']})

When you read a missing key, the docs say default_factory "is called without arguments to provide a default value for the given key, this value is inserted in the dictionary for the key, and returned."

Common factories

defaultdict(list)   # group items          d[k].append(x)
defaultdict(int)    # count, starts at 0   d[k] += 1
defaultdict(set)    # group unique items   d[k].add(x)

Nesting

nested = defaultdict(lambda: defaultdict(int))
nested['x']['y'] += 1
nested   # {'x': {'y': 1}}

A lambda is how you build a factory that needs more than a bare type.

4. Misconceptions and pitfalls

I ran each example below to confirm it.

You might think

Reading a key is harmless, so d['x'] is a safe way to peek.

Actually: every read of a missing key inserts it. Peeking pollutes the dict.

d = defaultdict(list)
d['m']          # []
d               # defaultdict(list, {'m': []})   (m is now a key)

You might think

key in d and d.get(key) also trigger the factory.

Actually: only d[key] does. The safe ways to peek are in and get().

d = defaultdict(list); d['m']
'x' in d        # False   (nothing inserted)
d.get('y')      # None    (factory bypassed, nothing inserted)
d               # defaultdict(list, {'m': []})

You might think

You pass the default value: defaultdict(0) or defaultdict([]).

Actually: you pass a callable that makes the value. Both lines raise TypeError: first argument must be callable or None. Use int, list, or lambda: 0.

defaultdict(int)         # ok, int() is 0
defaultdict(lambda: 0)   # ok
defaultdict(0)           # TypeError
defaultdict([])          # TypeError

Passing a callable also means each missing key gets its own fresh list, not one shared list.

You might think

A typo in a key still fails loudly, as with a normal dict.

Actually: a plain dict would raise KeyError, but defaultdict silently creates the misspelled key. This is the biggest trade-off of the tool.

d = defaultdict(int)
d['totl'] += 1
d['total'] += 1
d    # defaultdict(int, {'totl': 1, 'total': 1})   (two keys, one a typo)

You might think

The "default" behaviour stays attached when you pass the dict on.

Actually: it is still a defaultdict wherever it goes, so downstream code that reads a missing key keeps inserting. Convert with dict(d) when you are done building and want normal dict behaviour (also cleaner when printing or serialising).

d = defaultdict(list); d['a'].append(1)
dict(d)   # {'a': [1]}
